# SQL 查询优化 常用清单

> 慢查询大多不是数据库不行，而是索引没走对、返回了太多不需要的数据。

## 为什么值得关注

SQL 查询优化看起来不难，真正落地时细节很多。下面按我自己的理解整理一遍，方便以后回看。

## 核心要点

- 复合索引遵循最左前缀原则，把选择性高的列放前面。
- 避免在索引列上做函数运算，否则很容易退化成全表扫描。
- 先用执行计划确认扫描方式，再决定加不加索引。
- 分页很深时用游标（where id > ?）代替大偏移量。

## 具体做法

先跑通一个能工作的版本，再逐步补充异常处理和边界情况：

```sql
EXPLAIN ANALYZE
SELECT id, title, created_at
FROM articles
WHERE author_id = 42 AND created_at >= now() - interval '7 days'
ORDER BY created_at DESC
LIMIT 20;
```

跑起来之后，最先要看的不是结果对不对，而是失败时能不能快速定位。

## 注意事项

- 索引不是越多越好，写入放大和维护成本都要算进去。
- 统计信息过期会让优化器做出错误判断，定期更新。

## 小结

把SQL 查询优化拆成可验证的小步骤，比一次性追求完美更可靠。
